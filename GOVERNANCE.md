# Governance

WP24Horas Open Source is maintainer-led and contribution-friendly.

## Decision making

Maintainers are responsible for project direction, releases, security response and compatibility decisions. Contributions are evaluated on usefulness, maintainability, security, backward compatibility and fit with the repository's stated scope.

## Repository lifecycle

A public repository should remain public only when it is intentionally maintainable and independently useful. Historical experiments may be archived instead of presented as current engineering references.

## Releases

Projects should publish releases only after their documented quality/runtime gates pass. A version number in source code is not, by itself, evidence that a GitHub Release is ready.

## Automation

Repositories may use local-first validation and manual-only GitHub Actions to control CI consumption. Contributors should not change automation policy without discussing the operational impact.

## Security and privacy

Client code, proprietary product code, credentials, production data and other private material are out of scope for public repositories.

Repository-specific governance documents override this default where they exist.
